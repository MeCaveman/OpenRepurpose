# v0.9 — MCP, Local API, Webhooks and Headless Mode

## Release goal

Make OpenRepurpose scriptable and agent-friendly while preserving local security.

Interfaces:

```text
Web UI
CLI
REST API
MCP server
local webhook/event output
      |
      v
same application services
```

Support long-running headless operation for a home server/NAS/Linux box without creating a required cloud control plane.

## Codex recommendation

- Implementation: **GPT-5.6 Terra, Medium**.
- Use **GPT-5.6 Sol, High** for the threat model and MCP/API permission boundary.
- Luna for API docs/schema examples.
- Relative usage: **medium-high**.

## Threat model first

Before coding external-control interfaces, create/update an ADR covering:
- localhost malicious-webpage attacks;
- LAN exposure;
- bearer/token leakage;
- MCP clients with broad tool access;
- command injection;
- path traversal;
- webhook SSRF;
- untrusted workflow inputs;
- secret redaction.

Do not make "it only runs locally" the whole security model.

## REST API

Formalize `/api/v1`.

Required resource groups:
- health/version;
- accounts (safe metadata only);
- media;
- sources;
- workflows;
- jobs;
- schedules;
- transforms/transcripts where relevant;
- publish action.

Requirements:
- generated OpenAPI schema;
- Zod/request validation;
- stable error envelope;
- pagination;
- idempotency key support for create/publish operations where needed;
- no secret values returned;
- local authentication token/API key for non-browser clients;
- browser session/CSRF path remains separate or clearly designed.

## LAN/headless mode

Default remains loopback.

Explicit config can bind LAN interface.

When LAN mode is enabled:
- require auth;
- warn if plain HTTP is exposed beyond localhost;
- support user-supplied TLS cert/key or reverse proxy documentation;
- do not auto-open firewall ports;
- do not auto-configure router/UPnP.

## MCP server

Expose safe tools around existing application services.

Minimum tools:
- `get_status`
- `list_accounts`
- `list_media`
- `list_workflows`
- `list_jobs`
- `run_workflow`
- `publish_media`
- `schedule_workflow`
- `cancel_job`
- `get_job`

Do not expose:
- raw shell execution;
- arbitrary filesystem read;
- OAuth tokens/client secrets;
- unrestricted SQL;
- arbitrary FFmpeg strings.

Tool schemas validate all IDs/options.

### Destructive/high-impact actions
Publishing and scheduling are side-effecting.

Clearly mark/document side effects and require explicit arguments. If the MCP protocol/client supports user confirmation metadata or annotations, use current standard behavior.

## Webhook/event output

Allow a user to configure outbound webhooks for local events:
- job succeeded;
- job failed;
- workflow execution started/completed.

SSRF protections:
- by default permit localhost/private destinations only OR provide an explicit allowlist policy chosen in threat model;
- block link-local/cloud metadata endpoints;
- resolve/revalidate DNS carefully;
- configurable secret signature;
- timeout;
- bounded body;
- retry policy;
- never include credentials.

Do not make arbitrary URLs from source content trigger requests.

## Headless service

Support:

```text
openrepurpose start --headless
```

Document:
- Linux systemd unit example;
- Windows startup/service strategy if stable;
- Docker Compose option.

Docker remains optional and should mount:
- data;
- config;
- media paths intentionally.

Do not assume Docker can access arbitrary host media without mounts.

## CLI parity

Add commands needed to administer a headless instance:
```text
openrepurpose api token create
openrepurpose api token revoke
openrepurpose mcp start
openrepurpose config show
openrepurpose config set ...
openrepurpose backup create
```

Backup can be introduced here or completed in v1.0.

## Work packets

### Packet 1 — Threat model/ADR
Prefer **Sol High**. Keep the output concise and actionable.

### Packet 2 — API v1 schema
Refactor existing routes behind application services, generate OpenAPI, implement auth tokens and idempotency.

### Packet 3 — MCP
Implement MCP server as a thin mapping to safe services. Add protocol/schema tests.

### Packet 4 — Webhooks
Implement event subscription/delivery, signatures, SSRF protections and retry history.

### Packet 5 — Headless/LAN
Add explicit bind/auth/TLS configuration and service docs.

### Packet 6 — Docker
Create lean image/Compose example. Do not bake user credentials. Document FFmpeg/model volume behavior.

### Packet 7 — API/MCP E2E
Test:
- unauthorized call;
- duplicate idempotency key;
- malicious path;
- webhook to blocked metadata/link-local address;
- publish via MCP mock destination;
- cancellation;
- server restart.

## Acceptance criteria

- Same business logic serves UI, CLI, REST and MCP.
- No raw shell/filesystem/secret tools are exposed by MCP.
- LAN exposure is opt-in and authenticated.
- Webhook SSRF regression tests pass.
- OpenAPI spec is generated/tested.
- API tokens are revocable and stored safely.
- v0.8 DB migrates cleanly.
- Standard checks pass.

## Stop boundary

Plugin API stabilization, installers and 1.0 compatibility guarantees belong to v1.0.
