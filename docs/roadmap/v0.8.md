# v0.8 — Streamer Workflows: Twitch, Kick and OBS

## Release goal

Make OpenRepurpose particularly useful to streamers.

Target workflows:

```text
OBS replay/recording folder
        |
        v
 auto-settle/import
        |
 transform/captions
        |
 Shorts/Reels/TikTok
```

and, where official APIs permit:

```text
Twitch/Kick clip or VOD event
        |
 authorized media resolution
        |
 transform
        |
 destinations
```

## Codex recommendation

- Default: **GPT-5.6 Terra, Medium**.
- Sol only for API/security/event-ordering ambiguity.
- Luna for setup docs and UI cleanup.
- Relative usage: **medium-high**.

## Official API rule

Inspect current official Twitch and Kick developer documentation before implementation.

As of roadmap authoring:
- Twitch exposes clip/video APIs and current docs include clip download capabilities for authorized use cases.
- Kick exposes a public developer API/OAuth, but media download capabilities must be verified rather than assumed.

Use official endpoints when available.

Do not scrape authenticated webpages or extract browser cookies.

Optional external downloader fallback follows the rights rules from `AGENTS.md` and v0.4.

## OBS integration

Do **not** require an OBS plugin for the first implementation.

Support:
- watched recording folder preset;
- watched Replay Buffer folder preset;
- file-settle rules tuned for OBS output;
- filename pattern parser;
- optional sidecar JSON metadata import if provided by user tools;
- workflow trigger per folder.

Optional later in this version if simple:
- OBS WebSocket connection to receive recording/replay-save events.

If adding OBS WebSocket:
- use a maintained protocol client;
- credential stays local;
- integration remains optional;
- app still works with folder watching alone.

## Twitch source

Support current official capabilities useful for:
- account connection;
- selecting broadcaster;
- listing new clips;
- listing recent VOD metadata;
- event/poll-based detection;
- authorized clip download when current API permits;
- creating a clip from user's stream/VOD only if it fits product scope cleanly.

Keep VOD metadata vs downloadable media distinct. Do not claim download support when only metadata URL exists.

## Kick source

Support only capabilities exposed by current official Kick API.

Likely useful:
- OAuth account;
- channel/stream metadata;
- event/webhook/polling if officially supported;
- clips/VOD discovery only if official API exposes it.

If there is no official binary download:
- show source item metadata;
- allow local-original matching;
- allow optional authorized external resolver if enabled;
- document limitation.

## Stream workflow presets

Add guided presets:

### "OBS clip -> all short-form"
```text
OBS Replay Buffer folder
 -> wait for settled file
 -> 9:16 preset
 -> optional subtitles
 -> YouTube Shorts
 -> TikTok
 -> Instagram Reels
```

### "Stream VOD clip"
Source varies by supported platform API and user authorization.

Presets create normal editable workflows, not special hidden logic.

## Source event ordering

Remote platforms can deliver duplicate/out-of-order events.

Reuse source dedupe semantics:
- stable external ID;
- observed-at vs published-at;
- cursor/watermark;
- event ID when available;
- idempotent workflow execution.

## Work packets

### Packet 1 — OBS preset hardening
Improve folder watcher for OBS patterns, add presets/setup UI and tests with files that grow/rename.

### Packet 2 — Twitch research + ADR
Record current OAuth scopes, event/poll model, clip/VOD endpoints, authorized media download capability and rate limits.

### Packet 3 — Twitch adapter
Implement account/source discovery, polling/events and media resolver supported by official API.

### Packet 4 — Kick research + ADR
Record exact current public API capabilities and explicit limitations.

### Packet 5 — Kick adapter
Implement only verified capabilities; no placeholder fake downloading.

### Packet 6 — Workflow presets
Create streamer presets with capability validation and editable generated workflows.

### Packet 7 — Optional OBS WebSocket
Implement only if packets 1-6 are green and usage budget is healthy.

### Packet 8 — E2E/restart tests
Test duplicate events, out-of-order events, expired remote download URL, missing local original and platform token revocation.

## Acceptance criteria

- OBS local workflow works without Twitch/Kick accounts.
- Twitch capabilities are truthful and backed by official API behavior.
- Kick capabilities are truthful; unsupported download is shown as unsupported.
- No browser-cookie extraction.
- Remote source duplicates do not cause repeated destination publishes.
- v0.7 migrations pass.
- Standard checks pass.

## Stop boundary

Do not expose a general automation/MCP API until v0.9.
