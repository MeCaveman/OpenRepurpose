# v0.5 — Scheduling, Reliable Automation and Workflow UX

## Release goal

Make automation dependable enough to leave running unattended.

Add:
- one-time scheduled publishing;
- recurring schedules where meaningful;
- destination-specific publish timing;
- timezone/DST correctness;
- robust job concurrency/rate control;
- pause/resume/drain;
- a clearer visual workflow editor.

## Codex recommendation

- Use **GPT-5.6 Sol, High** for one bounded scheduler/queue semantics review.
- Implement with **GPT-5.6 Terra, Medium**.
- Use **Luna Medium** for UI/docs/test boilerplate.
- Relative usage: **high**.

## Scheduling model

Never store only local wall-clock strings.

Persist:
- IANA timezone ID;
- recurrence definition;
- next occurrence UTC instant;
- schedule status;
- last occurrence/result.

For one-time publish:
- store requested local representation for display;
- store resolved UTC instant for execution.

For recurring schedules:
- use a well-tested recurrence representation/library;
- define DST behavior explicitly;
- reject invalid/nonexistent local times or apply a documented policy;
- prevent duplicate execution after restart.

Do not implement a homegrown cron parser unless unavoidable.

## Schedule types

Required:
1. publish once at a date/time;
2. delay/hold destination until a date/time;
3. recurring source poll/workflow trigger using a supported recurrence rule;
4. optional time window ("only publish between 09:00 and 22:00") if it can be implemented cleanly.

## Job reliability

Add/refine:
- global worker concurrency;
- per-platform concurrency;
- per-account concurrency;
- rate-limit cooldown state;
- `Retry-After` support;
- circuit-breaker-like pause after repeated auth/permission failures;
- manual retry;
- retry failed destination only;
- queue pause/resume;
- graceful drain on shutdown;
- priority only if a real use case exists.

No Redis.

## Workflow UX

Introduce a visual workflow view using a maintained React node/edge library if justified.

Keep the semantic model in core; the diagram is only an editor/view.

Minimum node types:
- Source;
- Filter;
- Transform placeholder;
- Delay/Schedule;
- Destination.

v0.5 transform nodes can be placeholders/pass-through for features arriving in v0.6, but the persisted schema should support typed steps.

Rules:
- invalid graphs cannot be saved;
- cycles are rejected unless a future explicit loop feature exists;
- source must reach at least one destination;
- unsupported step ordering is explained;
- changing UI library must not change core workflow format.

Provide a simpler form editor fallback if visual editor becomes a usage sink. Correct semantics are more important than a fancy canvas.

## Execution model

Compile saved workflow graph into a validated execution plan.

Persist a versioned plan/snapshot:

```text
workflow definition
   |
 validate
   |
 compile
   |
 execution plan vN
   |
 jobs
```

Do not execute arbitrary JSON directly.

## Work packets

### Packet 1 — Scheduler ADR
With Sol High if available:
- define recurrence library/format;
- timezone/DST policy;
- restart semantics;
- uniqueness/idempotency;
- interactions with source poller and job runner.

Record ADR before implementation.

### Packet 2 — Schedule persistence/service
Implement schema, next-occurrence calculation, clock abstraction, scheduler loop and deterministic fake-clock tests.

### Packet 3 — Rate/concurrency controls
Implement per-platform/account limits, Retry-After cooldown, manual retry and queue controls.

### Packet 4 — Workflow plan model
Add typed steps, graph validation and compile-to-plan layer while migrating old v0.4 workflows.

### Packet 5 — Workflow UI
Implement visual or structured editor with Source/Filter/Schedule/Destination, validation and readable summary.

### Packet 6 — CLI
Add:
```text
openrepurpose schedule list
openrepurpose schedule show <id>
openrepurpose jobs retry <id>
openrepurpose jobs cancel <id>
openrepurpose jobs pause
openrepurpose jobs resume
```

### Packet 7 — Deterministic reliability tests
Use fake clock and mocked adapters for:
- restart one second before due;
- restart one second after due;
- DST spring-forward nonexistent time;
- DST fall-back repeated hour;
- remote `429 Retry-After`;
- account auth failure circuit pause;
- manual retry of only failed destination;
- source poll and publish due simultaneously.

## Acceptance criteria

- No duplicate scheduled execution across restart tests.
- All stored scheduled instants are unambiguous.
- UI displays the user's timezone and resolved next run.
- Rate-limit response does not hammer the API.
- Visual editor cannot produce a workflow the core cannot validate.
- v0.4 workflows migrate to the new plan model.
- Standard checks pass.

## Stop boundary

Transform nodes beyond pass-through/metadata preparation wait for v0.6.
