# v0.6 — Deterministic Media Transformation Pipeline

## Release goal

Add the media-processing part that makes OpenRepurpose a true repurposing tool.

A workflow can now do:

```text
source
  -> trim
  -> crop/pad/resize
  -> audio normalize
  -> optional watermark/text
  -> destination-specific encode
  -> publish
```

Transforms run locally with FFmpeg.

## Codex recommendation

- Default: **GPT-5.6 Terra, High** for media pipeline work.
- Escalate difficult filter-graph/cross-platform process bugs to **GPT-5.6 Sol, High**.
- Luna for presets/UI/docs.
- Relative usage: **high**.

## Design principles

### Recipe, not raw command
Users/workflows persist a typed transform recipe, never an arbitrary shell string.

Example conceptual model:

```json
{
  "steps": [
    {"type":"trim","startMs":1000,"endMs":61000},
    {"type":"fit","mode":"crop","width":1080,"height":1920,"anchor":"center"},
    {"type":"loudness","targetLufs":-14},
    {"type":"watermark","assetId":"...","position":"top-right"}
  ],
  "output": {
    "container":"mp4",
    "videoCodec":"h264",
    "audioCodec":"aac"
  }
}
```

Validate with Zod.

### Deterministic caching
Compute a transform cache key from:
- source fingerprint;
- normalized recipe;
- relevant encoder/tool version;
- output profile version.

Reuse an existing successful derivative when valid.

### Destination preparation
Keep:
- user transforms;
- destination compliance transforms;
separate in the model, even if FFmpeg executes them in one optimized command.

The user should know if OpenRepurpose changed a file just to meet a platform constraint.

## Required transforms

### Trim
- start/end;
- duration;
- frame/keyframe behavior documented.

### Fit
Modes:
- crop;
- contain/pad;
- stretch only if explicitly requested.

Presets:
- 9:16 1080x1920;
- 1:1 1080x1080;
- 16:9 1920x1080 or source-limited equivalent.

### Crop anchor
At least:
- center;
- top;
- bottom;
- left;
- right.

No AI face tracking yet.

### Audio
- preserve;
- normalize loudness;
- optional gain;
- remove audio.

### Overlay/watermark
- image;
- opacity;
- position;
- margin;
- scale.

### Text overlay
Only if font handling can be made cross-platform and predictable. Otherwise defer styled text to v0.7 subtitle system.

### Encode
- H.264/AAC MP4 baseline profile suitable for common platforms;
- CRF/quality preset;
- max resolution/frame rate controls;
- optional hardware acceleration only after reliable CPU path exists.

CPU/software encode is the reference implementation.

## Process management

Implement:
- structured progress parsing;
- cancellation;
- timeout/stall detection;
- child process cleanup;
- graceful app shutdown;
- no `shell: true`;
- temp-output then atomic finalize;
- disk-space preflight when possible;
- partial output cleanup.

Do not load media into JS memory.

## Hardware acceleration

Optional experimental capability:
- detect available encoders;
- allow user to opt in;
- automatically fall back to CPU only when doing so cannot change an explicitly required codec/profile unexpectedly;
- record encoder used in derivative provenance.

Do not make NVIDIA/Intel/AMD hardware a requirement.

## Workflow/UI

Transform node editor:
- presets first;
- advanced controls second;
- live metadata estimate, not full browser-side rendering;
- "test transform" creates a short preview derivative if feasible;
- display estimated/actual output properties.

CLI:
```text
openrepurpose media probe <id>
openrepurpose transform run <media-id> --preset vertical
openrepurpose transform inspect <derivative-id>
```

## Work packets

### Packet 1 — Transform domain + ADR
Define typed recipe, normalization, cache hash, derivative schema, provenance and user-vs-destination transform distinction.

### Packet 2 — FFmpeg command builder
Implement pure functions that compile recipes to executable+argument arrays.
Snapshot tests are useful, but also run real tiny-fixture integration tests in CI with FFmpeg.

### Packet 3 — Runner/progress/cancellation
Implement worker execution, temp output, progress, cancellation, crash cleanup and derivative records.

### Packet 4 — Core transforms
Trim, fit, crop anchors, encode.

### Packet 5 — Audio + watermark
Normalization/gain/remove-audio plus image overlay.

### Packet 6 — Workflow integration
Transform steps create/reuse derivatives before destination jobs. Ensure one derivative can serve multiple destinations when constraints match.

### Packet 7 — UI/CLI
Preset editor, custom dimensions, progress, cancellation, derivative inspection.

### Packet 8 — Stress/correctness tests
Test:
- spaces/unicode in paths;
- portrait/landscape sources;
- no-audio input;
- variable frame rate input;
- cancellation;
- full disk/error simulation where practical;
- corrupted input;
- cached reuse;
- two jobs request same derivative concurrently;
- process restart after partial output.

## Acceptance criteria

- No user-controlled value becomes shell syntax.
- Same source+recipe produces cache reuse.
- Concurrent identical transform requests do not race into corrupt output.
- Failed/cancelled transform never masquerades as complete.
- ffprobe confirms output dimensions/codecs expected by recipe.
- CPU path works on Windows and Linux CI/manual release tests.
- v0.5 workflows without transforms still work unchanged.

## Stop boundary

Speech transcription and subtitle generation wait for v0.7.
