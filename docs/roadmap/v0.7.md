# v0.7 — Local Transcription, Captions and Subtitle Rendering

## Release goal

Add useful local AI without requiring a cloud AI subscription.

Primary flow:

```text
video
  -> extract audio
  -> local Whisper-compatible transcription
  -> editable transcript/cues
  -> SRT/VTT
  -> optional burned captions
  -> publish
```

## Codex recommendation

- Default: **GPT-5.6 Terra, Medium**.
- Luna for caption-theme UI/docs.
- Sol only for difficult native-process/model-management issues.
- Relative usage: **medium**.

## Inference strategy

Prefer a local Whisper-compatible engine suitable for Windows/Linux, with `whisper.cpp` as the reference implementation unless a better maintained cross-platform option is established at implementation time.

Keep inference behind:

```text
TranscriptionProvider
```

so future providers can include:
- whisper.cpp;
- another local engine;
- optional user-configured cloud provider.

v0.7 ships local-first.

Do not require Python for the normal installation if it can be avoided.

## Model management

Do not silently download multi-GB models.

Implement:
- model catalog metadata;
- user-initiated download;
- download progress;
- checksum verification when authoritative hashes are available;
- configurable model storage path;
- delete model;
- available disk-space warning;
- clearly display model size/language/performance tradeoff.

Do not bundle every model in the app release.

## Transcription data

Persist separately from rendered subtitle files:
- transcript ID;
- media/derivative ID;
- provider;
- model/version;
- language;
- segments;
- start/end times;
- text;
- optional word timestamps if supported;
- generation timestamp;
- user edits.

User edits must not be overwritten when regenerating unless explicitly confirmed.

## Subtitle formats

Export:
- SRT;
- WebVTT.

Optional ASS can be used internally for styled burn-in if that gives more reliable styling.

## Caption rendering

Add a transform step:

```text
captions:
  source: transcript-id
  mode: burn-in | sidecar
  theme: ...
```

Themes at minimum:
- clean bottom captions;
- large centered short-form captions.

Controls:
- font;
- safe-area position;
- size;
- outline/shadow/background;
- max characters/line;
- line count;
- highlight current word only if word timestamps exist and implementation remains maintainable.

Cross-platform font behavior must be tested. Do not assume a Windows-only font exists on Linux.

## Workflow behavior

Transcription can be:
- explicit transform step;
- reused across workflows through cache/provenance.

Cache key includes source audio fingerprint + provider/model + relevant transcription options.

## UI

Add:
- Transcription page/panel on media item;
- model manager;
- generate/cancel;
- transcript editor;
- subtitle preview metadata;
- export SRT/VTT;
- workflow caption-step editor.

CLI:
```text
openrepurpose transcribe <media-id> --model <name>
openrepurpose transcript show <id>
openrepurpose transcript export <id> --format srt
```

## Work packets

### Packet 1 — Provider contract + transcript schema
Implement migrations, provider registry, cue models, cache semantics and tests.

### Packet 2 — whisper.cpp process bridge
Implement executable discovery/managed installation strategy, model location, process invocation, progress/cancellation and parser.

Never invoke through a shell string.

### Packet 3 — Model manager
Download/delete/list/checksum/disk-space UI and CLI support as appropriate.

### Packet 4 — Transcript editor/export
Implement editable segments plus deterministic SRT/VTT export.

### Packet 5 — FFmpeg caption rendering
Integrate sidecar and burn-in into v0.6 pipeline. Ensure escaping/path handling is safe.

### Packet 6 — Workflow integration
Add transcription/caption steps and cache reuse.

### Packet 7 — Tests
Cover:
- English and non-English UTF-8 text fixtures;
- cancelled transcription;
- missing model;
- corrupt model/error;
- transcript edit persistence;
- subtitle timestamp validation;
- font fallback;
- Windows/Linux paths.

## Acceptance criteria

- User can transcribe without OpenRepurpose sending media/audio to a cloud service.
- No model auto-download without action.
- User edits survive app restart.
- Generated SRT/VTT is valid for fixture transcripts.
- Burned captions produce a valid output derivative.
- Existing transform cache semantics remain correct.
- v0.6 DB migrates cleanly.

## Optional, only if usage remains

Add an **optional provider interface** for AI title/caption suggestions, but do not ship a mandatory API key or cloud dependency. Do not let this delay v0.7.

## Stop boundary

Twitch/Kick/OBS source specialization is v0.8.
