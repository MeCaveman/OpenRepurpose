# v0.4 — Remote Sources + Automatic Ingestion

## Release goal

Turn OpenRepurpose from a cross-poster into a real Repurpose.io-style automation engine.

Primary new flow:

```text
YouTube channel/source
       |
   new item detected
       |
       v
 authorized media resolution
       |
       v
   workflow snapshot
       |
       +--> destinations
```

Also formalize source polling, cursors, deduplication and source-item history.

## Codex recommendation

- Default: **GPT-5.6 Terra, Medium**.
- Use **Sol High** only for dedupe/idempotency/content-rights boundary design.
- Luna for docs/tests.
- Relative usage: **medium-high**.

## Rights and platform rule

Do not implement "download any public YouTube video."

A source item can be repurposed only when the user confirms they own or are authorized to reuse it.

Prefer, in order:
1. original local media already linked to the source item;
2. officially provided download/export mechanism;
3. an explicitly enabled external downloader integration for authorized content only, with a rights confirmation and documented platform-terms caveat.

Never bypass DRM, members-only/private access, authentication, or access restrictions.

## Source architecture

Formalize `SourceAdapter` around:
- account/source identity;
- polling/event capability;
- cursor;
- item stable ID;
- published time;
- metadata;
- resolution strategy;
- rights requirement;
- optional media availability.

Persist:
- source connection/config;
- cursor;
- observed item;
- dedupe key;
- resolution status;
- linked local media ID;
- workflow execution ID.

Polling the same item many times must create at most one execution for the same enabled workflow/version policy.

## YouTube source

Use YouTube Data API for **detection/metadata**.

Prefer efficient channel-upload playlist polling over expensive broad search when appropriate.

Features:
- connect/select a channel the user controls or explicitly configures;
- discover new uploads after a stored cursor/watermark;
- optional filters:
  - include/exclude Shorts-like durations;
  - title regex/substring;
  - privacy/availability where accessible;
  - published-after;
- ingest title/description/published timestamp/video ID;
- dedupe after restart.

Media resolution:
- support "match local original" first;
- optional external downloader adapter can be enabled by user;
- downloader must be an external process with version detection and safe argument arrays;
- no credential extraction from browsers;
- no bypass of protected content.

### Optional generic sources
If usage permits, add:
- RSS/Atom media enclosure source;
- podcast feed source.

These are lower priority than YouTube and may be deferred within v0.4 if the release gate is otherwise met.

## Workflow changes

Workflows now support:
- `local-folder:new-media`;
- `youtube:new-upload`;
- future source types through adapter registry.

Add source filters before job creation.

Store source-item metadata in the workflow execution snapshot.

Template variables:
- `{{source.title}}`
- `{{source.description}}`
- `{{source.publishedAt}}`
- `{{source.externalId}}`
- existing file/media variables when media resolves locally.

## Poll scheduler

This is not the full v0.5 scheduler.

Implement only a simple source poll loop:
- per-source next-poll time;
- configurable sane interval;
- persisted last success/error/cursor;
- jitter to avoid thundering herd;
- no polling faster than platform policy;
- pause source after repeated auth failure;
- graceful recovery after restart.

## Work packets

### Packet 1 — Source-domain design
Write ADR for source item/cursor/dedupe semantics.
Implement schema/migrations and generic source contract tests.

### Packet 2 — Source polling runner
Implement persisted poll scheduling/recovery independent of destination job runner while reusing common primitives where sensible.

### Packet 3 — YouTube detection
Implement YouTube channel/upload detection with mocked API tests and quota-conscious API calls.

### Packet 4 — Media resolution
Implement local-original matcher and generic `MediaResolver` contract.

Optionally implement an external downloader bridge behind explicit configuration and rights confirmation. Keep it fully separable.

### Packet 5 — Workflow integration
Add source filters, execution snapshots, template variables and exact-once-ish dedupe semantics.

"Exactly once" across remote APIs is not guaranteed; document the actual idempotency behavior precisely.

### Packet 6 — UI/CLI
UI:
- Sources page or accounts/source tab;
- YouTube source setup;
- last poll;
- last item;
- errors;
- pause/resume;
- workflow source selection.

CLI:
```text
openrepurpose sources list
openrepurpose sources add youtube
openrepurpose sources poll <id>
openrepurpose sources pause <id>
```

### Packet 7 — Restart/dedupe tests
Test:
- same page of source results returned repeatedly;
- process dies after item persistence but before job creation;
- process dies after job creation but before cursor advance;
- workflow disabled mid-poll;
- two workflows subscribe to same source;
- source item cannot resolve media.

## Acceptance criteria

- A mocked new YouTube upload automatically creates exactly the intended workflow execution(s).
- Restart scenarios do not cause uncontrolled duplicate publishing.
- Source polling does not use broad search unnecessarily.
- Rights confirmation is explicit for non-official download resolution.
- External downloader, if present, is optional and disabled by default.
- v0.3 DB migrates cleanly.
- Standard checks pass.

## Stop boundary

Do not implement user-defined calendar schedules or full transform pipelines yet.
