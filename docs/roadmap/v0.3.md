# v0.3 — Instagram Reels + Facebook Reels

## Release goal

Add Meta destinations using official APIs:

```text
local/source media
   |
   +--> YouTube
   +--> TikTok
   +--> Instagram Reels
   +--> Facebook Reels
```

Preserve a local-first design. Do not introduce an OpenRepurpose-hosted media relay.

## Codex recommendation

- Implementation: **GPT-5.6 Terra, Medium**.
- Use **GPT-5.6 Sol, High** for one review of OAuth, media-transfer method and async container/publish semantics.
- Tests/docs: **Luna Medium**.
- Relative usage: **high**.

## Important API constraint

Meta APIs change frequently. Codex must inspect current **official Meta documentation** before implementing.

For Instagram specifically, publishing may use a media-container flow and the supported method for getting local video bytes to Meta can change. Prefer current official resumable/local upload capabilities when available.

Do **not** silently start a public tunnel or upload the user's media to a third-party relay just to obtain a public URL.

If the current official API requires publicly reachable media and no direct/resumable local upload is available:
1. implement the adapter capability as unavailable for pure-local use;
2. document the limitation;
3. optionally support a user-configured media URL provider interface later;
4. do not add an OpenRepurpose cloud service.

## Scope

### Meta developer setup
Provide documentation/UI for:
- BYO Meta app;
- required products/permissions;
- callback URI;
- development vs live mode;
- app review requirements;
- Instagram account eligibility;
- Facebook Page eligibility.

Never promise support for ordinary accounts if the API requires professional/Page relationships.

### Account model
One OAuth identity can expose multiple publish targets.

Model targets separately from credentials:

```text
MetaCredential
  |
  +--> InstagramTarget(account/page relation)
  +--> FacebookPageTarget
```

Users can enable/disable targets independently.

### Instagram Reels destination
Implement current official flow:
- validate target eligibility;
- validate media constraints;
- upload/provide media using officially supported method;
- create media container if applicable;
- poll container processing;
- publish;
- store remote media ID/permalink if available;
- classify permission, processing and publishing failures separately.

### Facebook Reels destination
Implement current official Page Reels publishing flow:
- local/resumable upload when supported;
- upload/session lifecycle;
- publish/finalize;
- status polling;
- remote ID/permalink.

### Metadata
Expose only supported fields.

Keep a normalized common model but allow per-platform overrides.

### Job states
Meta publishing may have multiple remote async stages.

Do not overload a single string message. Persist structured step/progress:

```text
validating
uploading
remote_processing
publishing
verifying
succeeded/failed
```

Core jobs can still have the v0.1 state machine; store adapter progress/details separately.

## Acceptance criteria

- Pure localhost/self-hosted product remains functional.
- No automatic tunnel/third-party media relay.
- No secrets in browser bundle/logs.
- Instagram and Facebook targets are modeled separately.
- Async processing can resume/reconcile after restart.
- Unsupported account type produces an actionable explanation.
- Existing destinations remain compatible.
- Standard test suite and v0.2 -> v0.3 migration pass.

## Stop boundary

Do not build remote source monitoring yet.
