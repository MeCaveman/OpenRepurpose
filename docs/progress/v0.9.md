# v0.9 progress

## Completed
- Packet 1: added ADR 0012, a release-gating threat model for REST, MCP, webhooks, and opt-in
  LAN/headless control surfaces.
- Covered malicious localhost pages and DNS rebinding, LAN exposure, bearer leakage, MCP authority,
  command injection, path traversal, webhook SSRF, untrusted workflow input, and secret redaction.
- Packet 2: formalized `/api/v1` for health/version, safe accounts, media/import, sources,
  workflows, jobs/cancellation, schedules, transforms, transcripts, publishing, and token
  administration while preserving the legacy browser routes.
- Added an OpenAPI 3.1 document generated from the enforced strict Zod request contracts, stable
  error envelopes, bounded cursor pagination, and durable idempotency for create/import/publish
  operations.
- Added read/control API tokens with one-time disclosure, verifier-only SQLite persistence,
  header-only authentication, immediate revocation, and browser session/Origin/CSRF separation.
- Added migration `0025_api_v1`, v0.8 upgrade coverage, response DTO redaction for local paths and
  resumable upload URLs, and API boundary/security regression tests. No frontend code changed.

## Decisions
- ADR 0012 extends the existing local HTTP protections instead of replacing them; loopback remains
  the default and browser session/Origin/CSRF authority stays separate from machine credentials.
- API/MCP credentials are revocable, verifier-only at rest, header-only, and distinguish read from
  control authority. MCP remains an allowlisted application-service facade with no raw
  shell/filesystem/SQL/secret/FFmpeg surface.
- Outbound webhooks are default-deny and require an explicit endpoint allowlist entry for public,
  private, or loopback targets. Link-local, metadata, unspecified, multicast, and reserved targets
  remain blocked, with DNS/peer validation on every delivery.
- Packet 1 changed documentation only; each later packet owns implementation and regression
  evidence for its release-gating controls.
- `/api/v1` delegates to the existing application services; transport code validates and maps DTOs
  but does not duplicate media, job, workflow, source, schedule, transform, or transcript logic.
- Token creation is not response-cached because persisting its one-time plaintext result would
  violate verifier-only storage. Other replay-sensitive creation paths require `Idempotency-Key`.
- Persisted `pending` idempotency records fail closed after an interrupted request instead of
  risking a duplicate side effect.

## Known issues
- ADR 0012 still gates MCP authority, webhook SSRF, and LAN/headless controls until their owning
  later packets implement them.
- MCP, outbound webhooks, and opt-in LAN/headless controls remain unimplemented until their owning
  packets. API token CLI administration also remains in the later headless/CLI packet.
- An idempotency record interrupted while `pending` requires operator recovery; it intentionally
  remains fail-closed rather than expiring into a possible duplicate side effect.
