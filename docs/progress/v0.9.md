## Decisions
- ADR 0012 extends the existing local HTTP protections instead of replacing them; loopback remains
  the default and browser session/Origin/CSRF authority stays separate from machine credentials.
- API/MCP credentials are revocable, verifier-only at rest, header-only, and distinguish read from
  control authority. MCP remains an allowlisted application-service facade with no raw
  shell/filesystem/SQL/secret/FFmpeg surface.
- Outbound webhooks are default-deny and require an explicit endpoint allowlist entry for public,
  private, or loopback targets. Link-local, metadata, unspecified, multicast, and reserved targets
  remain blocked, with DNS/peer validation on every delivery.
- Packet 1 changed documentation only; each later packet owns implementation and regression
  evidence for its release-gating controls.
- `/api/v1` delegates to the existing application services; transport code validates and maps DTOs
  but does not duplicate media, job, workflow, source, schedule, transform, or transcript logic.
- Token creation is not response-cached because persisting its one-time plaintext result would
  violate verifier-only storage. Other replay-sensitive creation paths require `Idempotency-Key`.
- Persisted `pending` idempotency records fail closed after an interrupted request instead of
  risking a duplicate side effect.
- MCP remains an exported stdio transport and service facade; its later CLI launch command and
  LAN/headless authentication configuration remain owned by Packet 5. The current tool set has no
  shell, filesystem, secret, SQL, URL-fetch, or arbitrary FFmpeg capability.
- `schedule_workflow` intentionally maps only remote-source workflows to the existing durable
  source-poll scheduler; local watched-folder workflows do not acquire a speculative scheduler.
- Webhook configuration is default-deny: every public, private, or loopback endpoint must appear in
  `WEBHOOK_DESTINATIONS_JSON`; removing it disables the persisted destination and deletes its
  signing key. Source/workflow data never supplies a URL.
- Webhook delivery reuses `JobRunner` for bounded concurrency, retry timing, attempts, and restart
  behavior. A separate webhook delivery row stores only the safe immutable event envelope and
  classified HTTP outcome; it stores no signing secret or response body.
- `workflow.execution.completed` means the immutable workflow dispatch finished and its jobs were
  accepted, not that remote publishing completed. Terminal destination outcomes use the job events.

## Known issues
- ADR 0012 still gates opt-in LAN/headless controls until Packet 5 implements them. MCP CLI
  administration/launch and network transport authentication also remain in that packet.
- Webhook destinations are startup environment configuration in this packet; live CLI/config
  administration belongs to Packet 5. Delivery history is available through the application and
  repository boundary plus the shared job-attempt ledger; no frontend surface was added.
- An idempotency record interrupted while `pending` requires operator recovery; it intentionally
  remains fail-closed rather than expiring into a possible duplicate side effect.
- LAN browser access uses a startup environment secret so it can protect static assets before the
  application session exists. Operators should use HTTPS or a firewall-protected local reverse
  proxy; only health endpoints are intentionally unauthenticated for health checks.
