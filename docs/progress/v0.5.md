## Decisions

- Persist both schedules and immutable materialized occurrences; UTC due instants are authoritative
  and process-local timers are wake-up aids only.
- Use exactly pinned Croner 10 in Packet 2 as a five-field calculation/validation library, not as an
  in-memory executor. Recurring DST gaps are skipped and overlaps run once at the earlier instant.
- Catch up an overdue one-time schedule once. Coalesce multiple missed recurring instants into one
  recorded firing, then advance strictly beyond the recovery time.
- Dispatch through existing jobs with deterministic occurrence keys. The source poller remains the
  only source adapter caller, with one cadence owner per source connection and cooldown/pause taking
  precedence over scheduled poll requests.
- Schedule timing is persisted as UTC milliseconds; requested one-time wall time and IANA timezone
  are retained for audit. Repeated local times choose the earlier UTC instant and nonexistent local
  times are rejected.
- Destination job concurrency scope is snapshotted onto each job. Claims check SQLite running counts
  and control rows transactionally, so correctness does not depend on one in-memory worker process.
- Retry-After accepts delta-seconds and HTTP-date values. A response cooldown applies to both the
  affected platform and account; the later persisted deadline wins.
- Three auth/permission failures pause only the affected account by default. A successful scoped job
  clears the active account's failure count; a paused account requires explicit resume.
- Queue pause and drain stop new claims without cancelling work. Drain waits for the database-wide
  running count to reach zero, while normal server shutdown performs a non-persistent local drain.
- Manual retry is restricted to failed jobs, retains attempt history/checkpoints, and grants one new
  attempt. Source-execution retry continues to select failed destinations only.
- Workflow definitions are validated before compilation; plans allow only source, filter,
  pass-through transform, schedule, and destination steps. Persisted plan JSON is an audit snapshot:
  repositories recompile definitions on read and executors revalidate the typed plan, rather than
  treating stored JSON as executable instructions.

## Known issues

- Schedule UI/API/CLI surfaces are deferred to their owning packets; Packet 2 provides the
  application/service and persistence boundary only.
- Packet 6 owns the planned CLI commands for job retry/cancel/pause/resume; Packet 3 exposes the
  application/repository boundaries and protected HTTP controls without implementing later CLI work.
- Queue controls do not yet have a dedicated web UI; Packet 5 owns workflow UI work and later UX can
  consume the Packet 3 HTTP/application surfaces.
- Transform behavior remains a pass-through placeholder until v0.6; the Packet 5 editor exposes
  that boundary without implementing media operations.
- Schedule creation/listing and resolved next-run display remain outside the current HTTP/UI
  surface; the editor accepts an existing schedule ID and clearly leaves timing/timezone ownership
  with the durable scheduler.
