## Decisions
- v0.2 supports only Direct Post video uploads from local files (`FILE_UPLOAD`); no URL pulls,
  drafts, photos, scraping, browser automation, or audit workaround.
- Creator info is live, per-account preflight data rather than a static destination capability.
  Existing static `DestinationCapabilities` types remain unchanged; Packet 2 will add a
  TikTok-specific browser-safe preflight DTO.
- OAuth must choose a configured desktop loopback + required PKCE flow or HTTPS web/VPS flow.
  Tokens, PKCE verifiers, and sensitive upload URLs stay behind `SecretStore`.
- TikTok access and refresh tokens plus expirations/scopes are stored as one `SecretStore` bundle
  so a rotated refresh token replaces the previous bundle in one write; SQLite stores only safe
  identity and derived capability flags.
- TikTok does not expose developer-app audit status through creator-info. The UI distinguishes a
  creator offering public visibility from confirmed public-post availability and always surfaces
  the unaudited-client private-only restriction.

## Known issues
- TikTok unaudited clients are restricted to private viewing; a TikTok audit is an external
  requirement and its status is not exposed by creator-info.
- Packet 2 does not initialize or upload posts; live creator capabilities are preflight-only until
  Packet 3 adds the transport.
- Packet 3 must not persist TikTok's sensitive, expiring upload URL in an ordinary SQLite
  destination-job checkpoint and must avoid duplicate Direct Posts after recovery ambiguity.
