## Decisions
- OBS remains plugin-free: periodic scans are authoritative and filesystem identity preserves the
  existing durable cursor across a rename.
- OBS source behavior is stored in the normal workflow source step. No parallel watcher service or
  database migration is required.
- Recording settles for 10 seconds; Replay Buffer settles for 5 seconds. Standard folders continue
  to use `WATCH_SETTLE_MS`.
- Existing Direction E components and tokens express the setup UI, so OpenRepurpose Design System
  stays at 2.0 and `.interface-design/system.md` / `docs/UI_ARCHITECTURE.md` are unchanged.
- Twitch clip/VOD discovery is polling-authoritative because EventSub has no clip-created or
  VOD-published subscription. EventSub WebSocket may provide local-first wake-up hints, with an
  overlapping catch-up poll after every connection gap.
- Clip metadata remains distinct from binary availability. Authorized clip bytes use Twitch's
  temporary `Get Clips Download` URLs; VODs remain metadata-only because the official API exposes
  no VOD binary-download endpoint.
- Twitch source work reuses the existing account/secret, ADR 0006 source identity, official
  `MediaResolver`, managed staging, retry, and job boundaries. Packet 2 adds no runtime or UI code.
- Clip source metadata carries only stable IDs and browser-safe fields. The resolver streams the
  returned temporary landscape rendition (or portrait fallback) into managed staging and never
  persists a CDN URL. VODs deliberately expose local-original matching only.
- Twitch OAuth uses a high-entropy, browser-bound, single-use state and the registered local
  callback URI. Tokens, client secrets, and refresh-token rotation stay in `SecretStore`; every
  adapter use refreshes then validates the token and records a terminal authentication failure as
  a reauthorization requirement.
- Kick polling is authoritative for local installs because official real-time delivery is
  public-internet webhook only. The verified API exposes active channel/livestream metadata but no
  clip, VOD/history, playback, upload, or binary-download endpoint.
- Kick's livestream UUID is the remote source identity. Webhook message IDs deduplicate deliveries
  but do not replace source identity or justify advancing past an overlapping poll.
- Kick source observations are metadata-only and explicitly report official media as unavailable.
  The normal local-original matcher remains available; a separately enabled external resolver can
  receive a public channel locator only after explicit rights confirmation and is never represented
  as official Kick downloading.
- Packet 5 adds no frontend code or feature-local visual system. Existing source history presents
  the persisted media availability/limitation through its established shared components.
- Preset capability evaluation lives in a core application service and reads persisted account
  scopes, enabled Meta targets, active source configuration, and local FFmpeg availability. The UI
  presents the result and edits the returned normal `WorkflowInput`; it does not duplicate these
  rules or introduce a preset-only executor.
- An all-short-form preset includes the first capable YouTube, TikTok, and Instagram destination
  for each family. Missing families are visible and omitted only with a partial-route warning.
- Stream clip presets require an active Twitch `clips` source whose connected account has official
  clip-download capability. Twitch VOD and Kick metadata sources remain blocked because their
  official APIs do not expose media bytes.
- Existing Direction E components, token mappings, typography, 44px compact controls, and the
  1440px wide-workbench boundary express the preset UI. Design System 2.0 and the UI architecture
  remain unchanged.
- OBS WebSocket is an optional latency optimization, not a source or workflow type. It subscribes
  only to OBS output events and invokes the existing `WatchedFolderRunner.scan()` path, preserving
  folder-only behavior through OBS downtime, event gaps, duplicate events, and process restarts.
- OBS credentials never enter browser code or logs. `OBS_WEBSOCKET_PASSWORD` is an optional local
  startup bootstrap value copied into `SecretStore`; `ws://` is limited to loopback and remote OBS
  endpoints require certificate-validated `wss://`.

## Known issues
- Filesystems that expose neither a stable file ID nor stable creation time fall back safely to the
  path key; on those uncommon filesystems a rename restarts the settle window.
- Twitch `Get Clips Download` URLs are temporary and either landscape or portrait rendition may be
  unavailable; Packet 3 must resolve a fresh URL at execution/retry time and surface `null`
  renditions as media unavailable.
- Twitch provides no EventSub replay after an ungraceful WebSocket disconnect and no clip/VOD
  publication event, so Packet 3 must keep durable overlapping polling as the correctness path.
- Twitch exposes VOD metadata and authorized clip creation from a VOD, but no official full-VOD
  binary download. Packet 3 must not infer or scrape one.
- Kick's official developer surface does not expose clip/VOD discovery or media bytes. Packet 5 may
  provide account, channel, active-livestream, and optional webhook capabilities only; media must
  resolve through a user-matched local original or a separately enabled ADR 0009 resolver.
- Kick webhooks cannot target localhost directly and have no documented replay or ordering
  guarantee, so they cannot replace polling or require a hosted relay in the local-first baseline.
- Kick webhook subscription/reconciliation and signature-verified delivery remain optional future
  work. They are intentionally not enabled by the metadata polling baseline and must never replace
  durable polling.
- Presets intentionally select one capable destination per platform family. Additional accounts or
  targets can be selected in the generated workflow before saving; presets do not create duplicate
  routes for every connected account.
- OBS authentication failures and explicitly invalidated OBS sessions do not reconnect
  automatically; correct the local password/session configuration and restart the server. Folder
  scanning continues normally.
- Browser E2E verification is blocked in this managed Windows session because Chromium cannot be
  spawned (`EPERM` before test execution); no browser-facing code changed in Packet 7.
