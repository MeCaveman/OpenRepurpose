## Decisions

- Cursor/watermark state is an optimization and advances only after observed items/executions are
  durable; `(source connection, stable external ID)` is the correctness boundary.
- Event IDs are audit data, not item identity. The unique execution intent is
  `(source item, workflow key, workflow version)` with an immutable snapshot.
- Existing jobs remain the retry/lease engine and existing destination job records remain adapter
  checkpoints; source execution destinations add orchestration-level result state, not a parallel
  publisher.
- `delete_after_success` is the downloaded/generated-media default; `keep_for_duration` requires a
  positive duration; `keep_forever` never enters automatic cleanup.
- Only `openrepurpose_temporary` and `openrepurpose_generated` artifacts can be cleanup candidates.
  `user_owned_original` artifacts are permanently protected.
- Source scheduling jitter only increases the configured interval, so a source is never polled
  sooner than its configured minimum. Cursor advancement follows successful durable item/handoff
  persistence; replay after a crash is safe because item and job idempotency keys dedupe it.
- YouTube detection follows the official low-quota uploads-playlist pattern: `channels.list`
  obtains `contentDetails.relatedPlaylists.uploads`, `playlistItems.list` polls uploads (up to
  50 per page), and `videos.list` is used only for duration-dependent filtering. The adapter owns
  no downloader/resolver and reports only `local_original` as a future resolution strategy.

## Known issues

- No platform adapter is registered yet; Packet 3 supplies YouTube detection. Pending
  `source.item.observed` jobs are intentional handoff records until Packet 5 implements workflow
  execution integration.
- Media resolution/storage cleanup and workflow execution integration remain intentionally deferred
  to their owning packets.
- Exactly-once effects cannot be guaranteed across remote APIs when a remote acceptance and local
  checkpoint commit are separated by a crash; adapters must reconcile persisted remote operation
  IDs/idempotency keys and surface ambiguity instead of blindly republishing.
- YouTube source setup UI/CLI, source-connection management, local-original matching, and all
  remote media resolution remain deferred to their owning packets. The registered adapter expects
  a connection configuration containing a protected-account ID, which Packet 6 will expose.
