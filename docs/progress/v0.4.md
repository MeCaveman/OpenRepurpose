## Decisions

- Cursor/watermark state is an optimization and advances only after observed items/executions are
  durable; `(source connection, stable external ID)` is the correctness boundary.
- Event IDs are audit data, not item identity. The unique execution intent is
  `(source item, workflow key, workflow version)` with an immutable snapshot.
- Existing jobs remain the retry/lease engine and existing destination job records remain adapter
  checkpoints; source execution destinations add orchestration-level result state, not a parallel
  publisher.
- `delete_after_success` is the downloaded/generated-media default; `keep_for_duration` requires a
  positive duration; `keep_forever` never enters automatic cleanup.
- Only `openrepurpose_temporary` and `openrepurpose_generated` artifacts can be cleanup candidates.
  `user_owned_original` artifacts are permanently protected.
- Source scheduling jitter only increases the configured interval, so a source is never polled
  sooner than its configured minimum. Cursor advancement follows successful durable item/handoff
  persistence; replay after a crash is safe because item and job idempotency keys dedupe it.
- YouTube detection follows the official low-quota uploads-playlist pattern: `channels.list`
  obtains `contentDetails.relatedPlaylists.uploads`, `playlistItems.list` polls uploads (up to
  50 per page), and `videos.list` is used only for duration-dependent filtering. The adapter owns
  no downloader/resolver and reports only `local_original` as a future resolution strategy.
- Managed resolution paths are deterministic within a validated job/execution scope. The final
  path is persisted before acquisition so a finalized file can be registered after restart without
  downloading it again; incomplete `.partial` files are never registered and are removed safely.
- Resolver implementations receive only a managed staging path and `AbortSignal`. No external
  downloader is included in Packet 4; the generic contract keeps any future bridge optional and
  replaceable, and external resolution is blocked without explicit rights confirmation when the
  source descriptor requires it.
- Local originals remain in place and are recorded as `user_owned_original`/`protected`; only
  OpenRepurpose-owned temporary/generated artifacts are accepted by managed cleanup.
- A workflow snapshot version is the SHA-256 hash of its normalized execution-relevant source,
  filter, template, destination, and retention configuration. The unique
  `(source item, workflow key, workflow version)` constraint is the execution dedupe boundary.
- Destination job status and remote IDs are synchronized transactionally into the execution result
  rows. Queue leases/retries remain authoritative; Packet 5 adds no parallel publisher.
- Cleanup jobs are discovered from durable eligibility both after job settlement and at startup.
  A missing managed file during resumed cleanup is treated as already cleaned.
- Manual source polling simply marks an active source due for the server-owned headless poller;
  neither the web UI nor the CLI starts a competing polling process.

## Known issues

- Exactly-once effects cannot be guaranteed across remote APIs when a remote acceptance and local
  checkpoint commit are separated by a crash; adapters must reconcile persisted remote operation
  IDs/idempotency keys and surface ambiguity instead of blindly republishing.
- No official-download or external-downloader resolver implementation is included yet. The current
  YouTube source advertises local-original resolution only; a future external bridge must remain
  disabled by default, explicitly rights-gated, and comply with the Packet 4 resolver boundary.
- All current workflow destinations are required; the persistence/orchestration model supports
  optional destinations, but no Packet 5 user-facing workflow field exposes that choice.
- The current YouTube adapter remains local-original-only: items whose media cannot be matched to
  an authorized local original stay visibly unavailable for automatic resolution.
