# v0.3 progress

## Completed
- Packet 1: researched the current Meta v26 Instagram/Facebook publishing APIs and recorded the
  accepted OAuth, permission, account eligibility, direct local upload, asynchronous publish,
  constraints, limits, review, and callback boundary in ADR 0005.
- Confirmed that both Instagram and Facebook Page Reels accept local video bytes through Meta's
  `rupload.facebook.com`; no public media URL, tunnel, or hosted OpenRepurpose relay is required.
- Packet 2: added migration 0009 with separate Meta credential identities and independently enabled
  Facebook Page / linked Instagram professional targets. OAuth state, app credentials, user/Page
  tokens, token expiry, refresh, and target discovery stay behind `SecretStore`.
- Added the Meta Accounts UI and protected local API routes for BYO app setup, OAuth connection,
  target rediscovery, and per-target enablement. Discovered targets explain missing publish task or
  permission blockers without exposing secret material.

## Decisions
- v0.3 will use Facebook Login for Business so one credential can discover Page targets and linked
  Instagram professional targets; Business Login for Instagram is outside this release.
- Instagram direct upload uses a resumable media container and Facebook direct upload uses a Page
  video upload session. Remote IDs and async phases must be persisted before later transport work.
- Current v26 endpoint documentation wins over stale Postman/sample values: Instagram Reels are
  capped at 300 MB and 100 publishes per moving 24 hours; Facebook Page Reels allow 3–90 seconds
  and 30 publishes per moving 24 hours.
- Standard Access supports BYO apps serving owned/managed targets with app/business roles. Other
  users require Advanced Access, App Review, Business Verification, and a reviewer-accessible HTTPS
  deployment; OpenRepurpose will not create a tunnel.
- Target availability is based on the granted permissions returned by Meta and Page tasks, rather
  than OAuth success alone. Page tokens are retained per target for the later publishing packets.

## Known issues
- Meta's current permissions surfaces disagree about whether `pages_read_user_content` and ad
  permissions are conditional dependencies for some Page-role arrangements. Packet 2 must validate
  actual grants/tasks and expose an actionable blocker without requesting broad permissions by
  default.
- Meta documents Instagram local upload as resumable but does not document an offset-recovery query
  equivalent to Facebook's `bytes_transfered`; Packet 3 must recheck before promising restart-safe
  byte resumption.
- Meta may require conditional `pages_read_user_content` or ads permissions for some Business Manager
  roles; those are not requested by default and Packet 3 must surface the platform response.
