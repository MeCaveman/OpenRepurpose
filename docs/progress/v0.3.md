## Decisions
- v0.3 will use Facebook Login for Business so one credential can discover Page targets and linked
  Instagram professional targets; Business Login for Instagram is outside this release.
- Instagram direct upload uses a resumable media container and Facebook direct upload uses a Page
  video upload session. Remote IDs and async phases must be persisted before later transport work.
- Current v26 endpoint documentation wins over stale Postman/sample values: Instagram Reels are
  capped at 300 MB and 100 publishes per moving 24 hours; Facebook Page Reels allow 3–90 seconds
  and 30 publishes per moving 24 hours.
- Standard Access supports BYO apps serving owned/managed targets with app/business roles. Other
  users require Advanced Access, App Review, Business Verification, and a reviewer-accessible HTTPS
  deployment; OpenRepurpose will not create a tunnel.
- Target availability is based on the granted permissions returned by Meta and Page tasks, rather
  than OAuth success alone. Page tokens are retained per target for the later publishing packets.
- Instagram upload URIs remain in `SecretStore`, and never in SQLite checkpoints or logs. Because
  Meta does not document an Instagram upload-offset recovery query, a connection interruption after
  container creation fails safely rather than replaying unknown bytes or creating another container.
- Facebook upload URLs also remain in `SecretStore`; the durable checkpoint stores only the Page
  video ID, phase, confirmed byte count, and best-effort permalink.
- The workflow editor currently creates one destination per submission and does not yet expose
  per-platform metadata overrides; the underlying model supports the next UX packet.
- The Meta setup guide documents the current v0.3 callback and App Review boundary; public HTTPS
  deployment and review workflow remain deployment/user responsibilities until their roadmap packet.
- Rediscovery marks missing targets blocked, disables them, and removes their stored Page token.
  A target that later reappears must be explicitly re-enabled by the user.
- An Instagram checkpoint already in `publishing` is reconciled but never submitted again when
  Meta still reports the container as merely `FINISHED`; this favors duplicate prevention over an
  automatic retry when the prior publish outcome is ambiguous.

## Known issues
- Meta may require conditional `pages_read_user_content` or ads permissions for some Business Manager
  roles; those are not requested by default, and the returned Meta permission failure remains
  actionable rather than being treated as a generic processing error.
- Instagram has no documented byte-offset recovery query for resumable uploads. Interrupted uploads
  therefore require a user-initiated new publish job; OpenRepurpose will not replay them blindly.
- A Facebook finish request whose response is lost is deliberately not repeated automatically:
  OpenRepurpose preserves the Page video ID and requires reconciliation/a new user action rather
  than risking a duplicate publish.
- The workflow editor currently creates one destination per submission and does not yet expose
  per-platform metadata overrides; the underlying model supports the next UX packet.
