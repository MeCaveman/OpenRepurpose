# v0.6 progress

## Completed

- Packet 1 added versioned Zod schemas and TypeScript domain types for trim, fit, audio,
  watermark, MP4 output, layered transform plans, and derivative provenance.
- Added deterministic normalization, canonical serialization, recipe hashing, and cache identity
  over source fingerprint, normalized plan, output-profile version, FFmpeg version, and encoder.
- Added migration `0018_transform_derivatives` and matching Drizzle schema with provenance,
  lifecycle/output constraints, a unique cache key, and recovery-oriented indexes.
- Recorded the transform model, cache semantics, and user-vs-destination distinction in ADR 0008.
- Added domain and migration tests for defaults, validation, stable hashes, cache invalidation, and
  incomplete-output constraints.
- Packet 2 added a pure transform compiler that turns normalized plans into an FFmpeg executable
  and argument array. It compiles ordered user/destination steps, trim, fit/crop anchors, audio
  handling, watermark inputs, output limits, and CPU H.264/AAC MP4 encoding without shell strings.
- Added command-vector snapshots, shell-safety coverage for spaces/Unicode/command-looking paths,
  silent-input coverage, and a real tiny-fixture FFmpeg/ffprobe integration test.
- CI now installs FFmpeg on Ubuntu and Windows so the fixture integration test runs there.
- Packet 3 added an atomic SQLite derivative reservation repository with guarded lifecycle
  transitions, persisted structured FFmpeg progress, success invalidation, retry reset, and
  interrupted-run recovery.
- Added a spawn-safe FFmpeg process runner with key/value progress parsing, cooperative
  cancellation, absolute timeout and stall detection, TERM-to-KILL escalation, bounded stderr,
  and graceful shutdown cleanup.
- Added managed derivative storage with disk-space preflight, same-filesystem partial output,
  atomic rename finalization, exact-size cache validation, abandoned-scope cleanup, and path/
  symlink containment checks for Windows and Linux.
- Added the `media.transform` job handler and server composition. It validates source provenance,
  writes only to managed partial output, probes before finalization, persists output metadata,
  discards failed/cancelled output, and reuses only a validated successful derivative.
- Added centralized transform timeout settings and migration `0019_transform_progress`.
- Packet 4 hardened the reference CPU path: transform dimensions must be even for H.264/yuv420p,
  the compiler emits baseline-profile `libx264` plus 48 kHz/128 kbps AAC, and worker-side probing
  rejects outputs whose codec, audio, fitted dimensions, maximum dimensions, or frame rate do not
  match the typed plan before atomic finalization.
- Added coverage for all crop anchors, crop/contain/stretch fit modes, H.264-compatible dimension
  validation, CPU encode arguments, and rejection of an incorrect probed output codec.
- Packet 5 completed audio preserve, single-pass loudness normalization, gain, and audio removal
  compilation through the reference AAC/no-audio output paths.
- Image watermarks now resolve only through available local media assets with supported image
  extensions. The compiler passes their paths as discrete, looped FFmpeg input arguments and uses
  deterministic scale, opacity, position, margin, and source-bounded overlay behavior.
- Added worker, command-vector, and FFmpeg fixture coverage for safe image asset resolution,
  unavailable/invalid watermark rejection, audio filter ordering, audio removal, and combined
  normalize/gain/watermark output.
- Packet 6 integrates typed transform nodes into workflow execution. A normalized transform plan
  reserves one cache-keyed derivative and creates one `media.transform` prerequisite; compatible
  destination jobs fan out from that same derivative only after it succeeds.
- Added durable job prerequisites (migration `0020_job_dependencies`), including terminal
  dependency-failure propagation so blocked destination/source executions do not wait forever.
- Server composition now records the concrete FFmpeg build in cache provenance and exposes only
  validated successful derivatives to existing destination handlers through the media boundary.

## Decisions

- Persist typed/versioned transform intent, never FFmpeg command strings or filter fragments.
- Preserve ordered user transforms separately from optional destination compliance transforms.
- Use normalized plans for persistence and hashing; step array order remains significant.
- Treat only a validated `succeeded` derivative as cache-reusable; Packet 3 will implement the
  reservation and file-validation lifecycle.
- Defer styled text overlays until v0.7 establishes predictable cross-platform font handling.
- Keep FFmpeg invocation as an executable plus discrete arguments; watermark asset IDs resolve to
  local paths before compilation and are never embedded in filter syntax.
- Use FFmpeg's machine-readable `-progress pipe:1` protocol rather than parsing human stderr.
- Keep partial and final derivative files in the same managed filesystem scope so finalization is
  an atomic rename on both Windows and Linux.
- Treat process shutdown as a retryable interruption, cancellation as terminal, and a missing,
  changed, or wrong-sized cached file as invalid rather than reusable.
- Use the CPU `libx264` baseline profile with yuv420p and AAC at 48 kHz/128 kbps as the v0.6
  compatibility reference; hardware encoders remain deferred.
- Resolve watermark asset IDs at execution time through `MediaRepository`; recipe provenance keeps
  stable IDs while local paths stay out of persisted recipes and FFmpeg filter text.
- Loop static image inputs explicitly and bound overlays to the primary video stream so image
  demuxer defaults cannot shorten a derivative.
