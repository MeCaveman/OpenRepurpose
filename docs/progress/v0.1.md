## Decisions

- Core/application code depends on the `JobRepository` and `JobHandler` boundaries; SQLite and the in-process runner are replaceable adapters and do not depend on browser or request lifetime.
- Claims use SQLite `BEGIN IMMEDIATE` transactions. Completion, failure, heartbeat, and cancellation transitions require the active lease owner, preventing a stale worker from overwriting recovered work.
- A handler must throw `JobExecutionError` to opt into retry and provide a deliberately safe public code/message. Unexpected errors are non-retryable and persist only `UNEXPECTED_JOB_ERROR` / `Job execution failed.` so raw exceptions cannot leak secrets.
- The runner claims only registered handler types. Packet 5 starts the runtime with no production handlers; later destination packets register their own implementations without a central provider switch.
- Idempotency keys are globally unique foundations for later workflow/source/destination keys. Job inputs are JSON-cloned before enqueue and never updated after creation.
- Destination integrations receive credentials only through `AdapterContext.secretStore`; publish requests/results and capability DTOs deliberately contain no secret values and can be safely projected to browser APIs.
- Destination registration is composition-based and rejects duplicate IDs, so later integrations do not require provider switch statements in core/application code.
- `PlatformError` separates stable category/code/retry metadata and a safe public message from its internal cause. Later destination jobs can map this classification into the existing job failure boundary.
- `SecretStore` defines get/set/delete by scoped reference only. The in-memory implementation is test-only; Packet 7 must provide protected local persistence and an honest threat-model/setup path.
- Adapter logging uses a sink-independent structured logger that recursively redacts sensitive keys, authorization/query/label forms, registered literal secrets, errors, cycles, and binary values. Fastify additionally redacts common credential paths and never serializes raw error messages or stacks.
