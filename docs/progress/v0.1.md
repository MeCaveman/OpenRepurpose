# v0.1 progress

## Completed

- Packets 1–3: workspace/tooling, typed host-native configuration and SQLite migrations, plus the loopback Fastify/React security shell.
- Packet 4: added the `media_assets` migration and SQLite repository; core media import port/service; streaming SHA-256 fingerprinting and normalized local-file validation; executable discovery for FFmpeg/ffprobe; and an argument-array-only ffprobe JSON adapter.
- Added protected `GET /api/media` and `POST /api/media/import` routes, `openrepurpose media import <path>` and `media list [--json]`, and the `/media` import/library view. CLI, API, and UI use the same import service.
- Added focused coverage for paths with spaces and Unicode, fingerprint duplicate detection, persisted probe metadata, and a Windows-style path fixture supplied to ffprobe without shell interpolation.

## Decisions

- Imported media remains referenced in place: the normalized absolute local path, stable streaming content fingerprint, timestamps, size, and ffprobe metadata are persisted. No media bytes are copied or buffered in memory.
- `ffprobe` is selected from `FFPROBE_PATH`/`FFMPEG_PATH` or PATH and is always launched with `shell: false`, `windowsHide`, and argument arrays. Missing ffprobe leaves library listing available while import is unavailable.
- Media application contracts live in `@openrepurpose/core`; filesystem/ffprobe and SQLite are replaceable adapters. This preserves one implementation for local PCs, Docker, and VPS deployments.
- The root-only `/media/` ignore rule avoids accidentally ignoring the tracked `packages/media` source package.

## Migrations/configuration

- Added immutable migration `0002_media_assets`, creating `media_assets` with unique content fingerprint, availability state, file metadata, probe metadata, and a created-at index.
- Added `commander` for the Packet 4 CLI command surface. Optional `FFMPEG_PATH` and `FFPROBE_PATH` are read only at the executable-discovery composition boundary.
