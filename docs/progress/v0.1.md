## Decisions

- The initial deployment remains a local-first modular monolith. Durable behavior relies on explicit
  contracts and persistence, not shared process memory.
- Application paths use Windows AppData/LocalAppData or Linux XDG defaults. Absolute configuration
  overrides keep local PC, Docker, and VPS deployments on the same codebase.
- `@openrepurpose/db` uses Node 24's built-in SQLite driver through Drizzle's Node SQLite adapter.
  Migrations use `BEGIN IMMEDIATE` and a checksum ledger; ADR 0002 records the choice.
- Fastify runs with `trustProxy: false`. Packet 3 rejects non-loopback binding/public origins; LAN,
  VPS authentication, and explicit proxy trust remain deferred to their owning packets.
- Browser sessions use encrypted stateless cookies backed by a stable generated 32-byte local key.
  Mutating API requests require an allowed Host, exact Origin, and session-bound CSRF token. ADR
  0003 records the threat model and current official Fastify assumptions.
- Media, jobs, account, workflow, and platform-secret behavior remains deferred to later packets.

## Migrations/configuration

- Existing migration `0001_initial_settings` remains unchanged; Packet 3 adds no migrations.
- Typed configuration now includes `PORT`, `SESSION_KEY_PATH`, and optional `DEV_SERVER_URL` in
  addition to the existing paths, `BIND_HOST`, and `APP_URL`.
- `.env.example` documents production runtime and development proxy values. The session key defaults
  to `session.key` in the host-native configuration directory.
